# BR-miniloan-054@v1

## ข้อความของกฎ
Operations เห็นบัญชีสินเชื่อ (LoanAccount) ในหน้ารายการ/แดชบอร์ด และบันทึกการชำระ/ปิดบัญชีของบัญชีนั้นได้ เฉพาะบัญชีที่ตัวเองถูก assign ดูแลเท่านั้น — Operations คนอื่นที่ถือ role เดียวกันแต่ไม่ได้ถูก assign บัญชีนั้นทำไม่ได้ทั้งสองอย่าง · การ assign นี้ไม่ใช่กลไกแยกต่างหากที่สร้างขึ้นสำหรับงาน Servicing แต่สืบทอดมาจาก Loan Officer เดิมที่ดูแลใบสมัครซึ่งสร้างบัญชีนั้น (1 ใบสมัครที่ Disbursed สร้าง 1 บัญชี ตาม UL-miniloan-004) · ขอบเขตนี้ต้องถูกบังคับที่ฝั่ง API เช่นเดียวกับ BR-miniloan-033@v1 ไม่ใช่แค่ซ่อนปุ่มหรือซ่อนแถวบนหน้าจอ — เรียก API ด้วย id ของบัญชีที่ไม่ได้ถูก assign ต้องถูกปฏิเสธ · กลไกลำดับชั้น (หัวหน้าเห็นของลูกน้องไหม) และการโอนบัญชีให้ Operations คนอื่นดูแล ยังไม่ตัดสิน — ใช้คำถามค้างชุดเดียวกับ Loan Officer เพราะ assignment สืบทอดมาจากที่เดียวกัน (ดู DQ-miniloan-002, DQ-miniloan-003, DQ-miniloan-004) · เป็นกฎคนละข้อกับ BR-miniloan-034@v1 ซึ่งกำหนดว่า role ไหน (Operations vs Applicant) ทำอะไรได้ — ข้อนี้กำหนดว่าในบรรดา Operations ด้วยกัน คนไหนทำกับบัญชีไหนได้

## ที่มา

> "Operations ที่บันทึกการชำระ/ปิดบัญชีต้องเป็นคนที่ถูก assign ดูแลบัญชีนั้นโดยเฉพาะ · เห็นเฉพาะบัญชีที่ตัวเองถูก assign ในหน้ารายการ/แดชบอร์ด · สืบทอดจาก Loan Officer เดิมของใบสมัคร ไม่ใช่กลไกแยกสำหรับ Servicing"
> — [SRC-020](../sources/SRC-020.md) หน้า — §[1]-[2],[4]-[5]

## พิสูจน์โดย

- [EX-miniloan-150](../examples/EX-miniloan-150.md) — happy: ระบบรับชำระตามปกติ — แสดง **"บันทึกการชำระเรียบร้อย"** และงวดนั้นเปลี่ยนเป็น **"จ่ายแล้ว"** ตาม BR-miniloan-020@v1 · ปุ่ม **"บันทึกการชำระ"** และ **"ปิดบัญชี"** บนหน้าบัญชี X แสดงให้กดได้ตามปกติสำหรับ ก. เพราะเป็นบัญชีที่ตัวเองถูก assign ดูแล
- [EX-miniloan-151](../examples/EX-miniloan-151.md) — exception: ทั้งสองคำสั่งถูก API ปฏิเสธเหมือนกัน — **"ไม่มีสิทธิ์ดำเนินการกับบัญชีสินเชื่อนี้ — ไม่ได้ถูก assign ดูแลบัญชีนี้"** ตาม BR-miniloan-025@v1 · บัญชี Y ไม่มีการเปลี่ยนแปลงใดๆ ทั้งยอดคงเหลือและสถานะ · **การปฏิเสธเกิดที่ฝั่ง API ไม่ใช่แค่ไม่มีปุ่มบนหน้าจอ** — ถ้ากันแค่บนหน้าจอ คำสั่งเรียก API ตรงนี้จะผ่าน
- [EX-miniloan-152](../examples/EX-miniloan-152.md) — boundary: เห็นเฉพาะบัญชี X ในรายการและในยอดสรุป — **ไม่มีบัญชีของ Operations คนอื่นหลุดเข้ามาแม้แต่บัญชีเดียว** และจำนวนรายการที่เห็นตรงกับจำนวนบัญชีที่ ก. ถูก assign เท่านั้น · **ช่องโหว่ของขอบเขตข้อมูลมักอยู่ที่การเรียกแบบรายการ ไม่ใช่รายบัญชี** เพราะรายบัญชีมักมีการตรวจ แต่รายการมักลืม
