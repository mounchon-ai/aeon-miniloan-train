# BR-miniloan-044@v1

## ข้อความของกฎ
ตารางผ่อนที่ออกให้ผู้กู้แล้วหลังเบิกจ่าย แก้แถวในฉบับเดิมไม่ได้ — ถ้าต้องเปลี่ยน ต้องออกตารางผ่อนฉบับใหม่ทับทั้งฉบับ และฉบับเดิมต้องเก็บไว้ดูย้อนหลังได้ ห้ามลบ

## ที่มา

> "ตารางผ่อนที่ออกให้ผู้กู้แล้วหลังเบิกจ่าย แก้แถวในฉบับเดิมไม่ได้ ต้องออกตารางผ่อนฉบับใหม่ทับทั้งฉบับ และฉบับเดิมต้องเก็บไว้ดูย้อนหลังได้ ห้ามลบ"
> — [SRC-006](../sources/SRC-006.md) หน้า — §[3] QB-frz-02

## พิสูจน์โดย

- [EX-miniloan-008](../examples/EX-miniloan-008.md) — happy: หน้า "ตารางผ่อน" แสดง "ฉบับที่ 2 (ใช้อยู่) — ออกเมื่อ {วันที่ออกฉบับใหม่}" เป็นตารางที่ใช้จริง และมีตัวเลือก "ดูฉบับก่อนหน้า" ที่เปิดฉบับที่ 1 ขึ้นมาดูได้ครบทุกแถว โดยฉบับที่ 1 กำกับว่า "ฉบับที่ 1 — ถูกแทนที่เมื่อ {วันที่ออกฉบับใหม่}"
- [EX-miniloan-009](../examples/EX-miniloan-009.md) — exception: ทั้งสองทางถูกปฏิเสธเหมือนกัน — แสดงข้อความ "แก้ตารางผ่อนรายงวดไม่ได้ — ถ้าต้องเปลี่ยน ให้ออกตารางผ่อนฉบับใหม่ทับทั้งฉบับ" และ API ปฏิเสธด้วยเช่นกันตาม BR-miniloan-025@v1 · แถวงวดที่ 7 ยังคงค่าเดิมทุกช่อง
- [EX-miniloan-010](../examples/EX-miniloan-010.md) — exception: ระบบปฏิเสธ และแสดงข้อความ "ลบตารางผ่อนฉบับเก่าไม่ได้ — ฉบับที่ถูกแทนที่ต้องเก็บไว้ให้ดูย้อนหลังได้" · ฉบับที่ 1 ยังเปิดดูได้ครบทุกแถวตามเดิม
- [EX-miniloan-011](../examples/EX-miniloan-011.md) — boundary: หน้า "ตารางผ่อน" แสดง "ฉบับที่ 3 (ใช้อยู่)" เป็นตารางที่ใช้จริง · รายการฉบับก่อนหน้าแสดงทั้ง "ฉบับที่ 1" และ "ฉบับที่ 2" และเปิดดูได้ทั้งคู่ ไม่มีฉบับใดหายไป · มีฉบับที่กำกับว่า "ใช้อยู่" ได้เพียงฉบับเดียวเสมอ
