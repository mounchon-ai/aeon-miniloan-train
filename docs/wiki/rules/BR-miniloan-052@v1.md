# BR-miniloan-052@v1

## ข้อความของกฎ
ถ้ายอดส่วนที่เกินมากกว่ายอดปิดบัญชีตาม BR-miniloan-022@v1 ระบบต้อง**ปฏิเสธการบันทึกทั้งรายการ** — ไม่บันทึกการชำระ ไม่ปิดงวด ไม่ตัดเงินต้น ไม่ออกตารางผ่อนฉบับใหม่ และไม่ปิดบัญชี · ต้องแจ้ง Operations พร้อมยอดปิดบัญชีที่ถูกต้อง เพื่อบันทึกใหม่ด้วยยอดที่ทำให้ส่วนเกินเท่ากับยอดปิดบัญชีพอดี · **ไม่มีการทอนคืนและไม่มียอดค้างของผู้สมัครเก็บไว้ในระบบ** — เงินส่วนที่จ่ายเกินไปจริงถูกจัดการนอกระบบ ตามกรอบที่ตกลงไว้ว่าระบบบันทึกผลของการชำระที่เกิดขึ้นข้างนอกไปแล้ว ไม่ใช่ระบบรับเงินเอง · ผลที่ยอมรับแล้วคือระเบียนในระบบจะไม่ตรงกับเงินที่เคลื่อนจริงในกรณีนี้ จนกว่า Operations จะบันทึกใหม่ให้พอดี · ข้อจำกัดนี้ต้องบังคับที่ฝั่ง API ตาม BR-miniloan-025@v1 ไม่ใช่แค่กันที่หน้าจอ

## ที่มา

> "ตอบ b : ปฏิเสธทั้งรายการ ให้ Operations บันทึกใหม่ให้พอดียอดปิดบัญชี"
> — [SRC-015](../sources/SRC-015.md) หน้า — §[2] Q-miniloan-014 ท่อน 1

## พิสูจน์โดย

- [EX-miniloan-117](../examples/EX-miniloan-117.md) — exception: ระบบ **ปฏิเสธการบันทึกทั้งรายการ** — ไม่บันทึกการชำระ ไม่ปิดงวด ไม่ตัดเงินต้น ไม่ออกตารางผ่อนฉบับใหม่ และไม่ปิดบัญชี · แจ้ง **"บันทึกไม่ได้ — ยอดชำระเกินยอดปิดบัญชี 4,300.00 บาท · ยอดปิดบัญชีที่ถูกต้องคือ 50,700.00 บาท กรุณาบันทึกใหม่ให้พอดี"** · **ไม่มีการทอนคืนและไม่มียอดค้างของผู้สมัครเก็บไว้ในระบบ** — เงินส่วนที่จ่ายเกินไปจริงจัดการนอกระบบ
- [EX-miniloan-118](../examples/EX-miniloan-118.md) — boundary: **ถูกปฏิเสธทั้งรายการ** เช่นเดียวกับกรณีเกิน 4,300 บาท — **เกินแม้สตางค์เดียวก็ไม่ใช่การปิดบัญชี** · เทียบกับ EX ก่อนหน้าที่ 50,700.00 พอดีปิดได้ และ 50,699.99 เป็นการโปะ · **สามทางนี้แยกกันที่จุดเดียวกันเป๊ะ ไม่มีช่วงคาบเกี่ยว**
- [EX-miniloan-119](../examples/EX-miniloan-119.md) — exception: API ปฏิเสธด้วยเหตุผลเดียวกัน — **การบังคับเกิดที่ฝั่ง API ตาม BR-miniloan-025@v1 ไม่ใช่แค่ปุ่มบนหน้าจอที่กดไม่ได้** · สถานะบัญชีและตารางผ่อนไม่ถูกแตะต้อง
