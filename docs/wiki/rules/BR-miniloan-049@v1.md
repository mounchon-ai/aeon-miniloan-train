# BR-miniloan-049@v1

## ข้อความของกฎ
ผู้อนุมัติคำขอปรับปรุงบัญชีสินเชื่อที่ปิดแล้วต้องเป็นคนละคนกับผู้ขอแก้ (four-eyes) — ผู้ที่ยื่นคำขออนุมัติคำขอของตัวเองไม่ได้ แม้จะถือ role ผู้อนุมัติที่ตั้งไว้ตาม BR-miniloan-039@v1 · ข้อห้ามนี้ต้องบังคับที่ฝั่ง API ตาม BR-miniloan-025@v1 ไม่ใช่แค่ซ่อนปุ่มบนหน้าจอ

## ที่มา

> "บังคับ four-eyes คือผู้อนุมัติต้องเป็นคนละคนกับผู้ขอแก้ เพราะผู้ขอแก้มักเป็น Operations ซึ่งเป็นคนบันทึกยอดผิด"
> — [SRC-012](../sources/SRC-012.md) หน้า — §[2] Q-miniloan-009 ท่อนที่ 2

## พิสูจน์โดย

- [EX-miniloan-077](../examples/EX-miniloan-077.md) — happy: ระบบแยกเป็นสองขั้นชัดเจน — ตอนยื่นแสดง "ส่งคำขอปรับปรุงบัญชีที่ปิดแล้วเรียบร้อย — รออนุมัติจาก {role ผู้อนุมัติ}" และหลัง ข. อนุมัติแสดง "อนุมัติคำขอปรับปรุงแล้ว — การแก้ไขมีผลเมื่อ {เวลาอนุมัติ}" · ค่าบนบัญชีเปลี่ยนเป็นค่าใหม่ก็ต่อเมื่อผ่านขั้นที่สองแล้วเท่านั้น · ผู้ขอแก้ (ก.) กับผู้อนุมัติ (ข.) เป็นคนละคน ซึ่งเป็นเงื่อนไขที่ BR-miniloan-049@v1 บังคับไว้
- [EX-miniloan-080](../examples/EX-miniloan-080.md) — exception: ทั้งสองทางถูกปฏิเสธ — ปุ่ม "อนุมัติ" บนคำขอที่ตัวเองยื่นแสดงเป็นสถานะกดไม่ได้ และ API ปฏิเสธด้วยข้อความ "อนุมัติคำขอของตัวเองไม่ได้ — ผู้อนุมัติต้องเป็นคนละคนกับผู้ขอแก้" ตาม BR-miniloan-025@v1 · คำขอยังอยู่ในสถานะ "รออนุมัติ" และค่าบนบัญชียังไม่เปลี่ยน — ถือ role ผู้อนุมัติยังไม่พอ ต้องเป็นคนละคนด้วย
