# EX-miniloan-077

## กำหนดให้ (given)
บัญชีสินเชื่อสถานะ Closed ที่พบภายหลังว่ายอดชำระงวดสุดท้ายถูกบันทึกผิด · ระบบตั้ง role ผู้อนุมัติไว้แล้วตาม BR-miniloan-039@v1 · Operations ก. เป็นผู้พบข้อผิดพลาด ส่วน Loan Officer ข. เป็นผู้ถือ role ผู้อนุมัติ — คนละคนกัน

## เมื่อ (when)
ก. ยื่นคำขอปรับปรุงยอดชำระงวดสุดท้าย จากนั้น ข. เปิดคำขอนั้นและกดอนุมัติ

## แล้ว (then)
ระบบแยกเป็นสองขั้นชัดเจน — ตอนยื่นแสดง "ส่งคำขอปรับปรุงบัญชีที่ปิดแล้วเรียบร้อย — รออนุมัติจาก {role ผู้อนุมัติ}" และหลัง ข. อนุมัติแสดง "อนุมัติคำขอปรับปรุงแล้ว — การแก้ไขมีผลเมื่อ {เวลาอนุมัติ}" · ค่าบนบัญชีเปลี่ยนเป็นค่าใหม่ก็ต่อเมื่อผ่านขั้นที่สองแล้วเท่านั้น · ผู้ขอแก้ (ก.) กับผู้อนุมัติ (ข.) เป็นคนละคน ซึ่งเป็นเงื่อนไขที่ BR-miniloan-049@v1 บังคับไว้

## พิสูจน์กฎ

- [BR-miniloan-038@v1](../rules/BR-miniloan-038@v1.md) ✅ ปัจจุบัน — แก้ข้อมูลของบัญชีสินเชื่อที่ปิดแล้ว (Closed) ทำได้ แต่ต้องผ่านการอนุมัติก่อนจึงมีผล — แก้ทับทันทีไม่ได้ และการยกเลิกบัญชีทิ้งอย่างเดียวก็ไม่ใช่ทางแก้
- [BR-miniloan-049@v1](../rules/BR-miniloan-049@v1.md) ✅ ปัจจุบัน — ผู้อนุมัติคำขอปรับปรุงบัญชีสินเชื่อที่ปิดแล้วต้องเป็นคนละคนกับผู้ขอแก้ (four-eyes) — ผู้ที่ยื่นคำขออนุมัติคำขอของตัวเองไม่ได้ แม้จะถือ role ผู้อนุมัติที่ตั้งไว้ตาม BR-miniloan-039@v1 · ข้อห้ามนี้ต้องบังคับที่ฝั่ง API ตาม BR-miniloan-025@v1 ไม่ใช่แค่ซ่อนปุ่มบนหน้าจอ
