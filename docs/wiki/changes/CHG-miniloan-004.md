# CHG-miniloan-004

## ทำไมถึงเปลี่ยน
Q-miniloan-015 ข้อ (2) สั่งให้ขยายเงื่อนไขของ BR-miniloan-052@v1 จาก "ส่วนเกินมากกว่ายอดปิดบัญชี" ให้ครอบ "ส่วนเกินหลังหักค่าธรรมเนียมการโปะมากกว่าเงินต้นคงเหลือ" ด้วย — BR-miniloan-050@v2 (CHG-miniloan-003) อ้างถึงกฎข้อนี้ไปแล้วในฐานะปลายทางของการปฏิเสธ แต่เงื่อนไขเดิมยังไม่ครอบกรณีนั้นจริง ผลลัพธ์เหมือนกันทั้งสองทริกเกอร์จึงรวมเป็นเงื่อนไข OR เดียว ไม่แยกเป็นกฎคนละข้อ

## หมายเหตุ
ไม่มี CALC ผูกกับ BR-miniloan-052 โดยตรง และไม่มี golden dataset ใดพิสูจน์ BR-miniloan-052 เลย จึงไม่มีอะไรถูกทำให้ใช้ไม่ได้ · ทั้งสามตัวอย่างเดิม (EX-miniloan-117 exception · EX-miniloan-118 boundary · EX-miniloan-119 exception) ยังพิสูจน์ @v2 ได้ครบเหมือนเดิมตามการยืนยันของเจ้าของสเปก เพราะทั้งสามใบพิสูจน์เฉพาะทริกเกอร์เดิม (ส่วนเกินมากกว่ายอดปิดบัญชี) — **ทริกเกอร์ใหม่ (ส่วนเกินหลังหักค่าธรรมเนียมมากกว่าเงินต้นคงเหลือ) ยังไม่มีใครพิสูจน์** ต้องตามด้วย /req:example BR-miniloan-052@v2 · เมื่อรวมกับ /req:example BR-miniloan-050@v2 ที่ค้างจาก CHG-miniloan-003 แล้ว ทั้งสองรอบพิสูจน์เส้นทางเดียวกัน (ปฏิเสธเมื่อเงินต้นจะติดลบ) จากมุมของคนละกฎ — ควรวางแผนตัวอย่างร่วมกัน ไม่ใช่คนละรอบแยกอิสระ · BR-miniloan-051@v1 (ตารางเทียบสามทาง) ยังไม่ถูกขึ้นเวอร์ชันในรอบนี้เช่นเดิม รายงานไว้เฉยๆ
