# CHG-miniloan-003

## ทำไมถึงเปลี่ยน
Q-miniloan-015 ถูกตอบแล้ว: กรณีที่ส่วนเกินหลังหักค่าธรรมเนียมการโปะ 1% แล้วมากกว่าเงินต้นคงเหลือ ให้ปฏิเสธการบันทึกทั้งรายการ เช่นเดียวกับ BR-miniloan-052@v1 — ไม่ตัดเท่าที่เหลือแล้วทอนคืนส่วนล้น และไม่ถือเป็นการปิดบัญชีก่อนกำหนด · ประโยค "ยังไม่ตัดสิน (ดู Q-miniloan-015)" ที่ค้างอยู่ในข้อความของ BR-miniloan-050@v1 จึงตกยุคและต้องถูกแทนที่ด้วยผลการตัดสิน

## หมายเหตุ
ไม่มี CALC ผูกกับ BR-miniloan-050 โดยตรง และไม่มี golden dataset ใดพิสูจน์ BR-miniloan-050 เลย (GD-miniloan-001 พิสูจน์ CALC-miniloan-001@v1/BR-miniloan-016@v1 เท่านั้น) จึงไม่มีอะไรถูกทำให้ใช้ไม่ได้ · ทั้งสามตัวอย่างเดิม (EX-miniloan-111 happy · EX-miniloan-112 boundary · EX-miniloan-113 alternate) ยังพิสูจน์ @v2 ได้ครบเหมือนเดิมตามการยืนยันของเจ้าของสเปก เพราะไม่มีใบไหนแตะช่วงที่ส่วนเกินหลังหักค่าธรรมเนียมมากกว่าเงินต้นคงเหลือ — ท่อนใหม่ (เส้นปฏิเสธเมื่อเงินต้นจะติดลบ) จึงยังไม่มีใครพิสูจน์ ต้องตามด้วย /req:example BR-miniloan-050@v2 เป็นขั้นแยกที่อนุมัติแล้วเท่านั้น · ยังไม่ได้ขยายเงื่อนไขของ BR-miniloan-052@v1 ให้ครอบกรณีนี้ตามสิ่งที่ Q-miniloan-015 ข้อ (2) ชี้ไว้ — ต้องตามด้วย /req:change BR-miniloan-052 แยกต่างหาก มิฉะนั้นสิ่งที่ BR-miniloan-050@v2 อ้างถึง ("เช่นเดียวกับ BR-miniloan-052@v1") จะไม่มีเงื่อนไขในกฎนั้นรองรับจริง · BR-miniloan-051@v1 (ตารางเทียบสามทาง: เท่ากับ/น้อยกว่า/มากกว่ายอดปิดบัญชี) ก็ไม่ครบถ้วนอีกต่อไป เพราะทริกเกอร์ใหม่นี้ซ่อนอยู่ในสาขา "น้อยกว่า" ของมันเอง — รายงานไว้ให้เจ้าของสเปกพิจารณา ยังไม่ขึ้นเวอร์ชันให้ในรอบนี้
