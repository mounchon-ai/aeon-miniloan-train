## เนื้อความ

> บันทึกคำตอบจากรอบ /req:ask ชั้น 1 (framing) รอบ B — actors x2 + language x1 — พี่ปูเป็นผู้ตัดสิน ทุกข้อเลือกตัวเลือกที่ระบบเสนอไว้ (ดาว) [1] QB-actor-01 (ชั้น 1 รอบ B · 2026-08-24) — นอกจาก Applicant / Loan Officer / หัวหน้าเจ้าหน้าที่สินเชื่อ / Operations / System / Web / API ที่มีอยู่แล้ว ไม่มีผู้เกี่ยวข้องเพิ่ม — ไม่มี scheduled job และไม่มีคนนอกองค์กรเพิ่มเติม (ยืนยันชุดเดิม ไม่เปิดโหนดใหม่) [2] QB-actor-02 (ชั้น 1 รอบ B · 2026-08-24) — Applicant ห้ามทำสิ่งที่ย้อนกลับไม่ได้ — คำตอบตรงกับที่มีอยู่แล้วใน BR-miniloan-031@v2 (provenance SRC-002 [1]) ทุกประการ ถือเป็นการยืนยันซ้ำ (♻️ SAME) ไม่เปิดกฎใหม่ [3] QB-lang-01 (ชั้น 1 รอบ B · 2026-08-24) — "บทบาทผู้อนุมัติ / ApproverRole" (UL-miniloan-016 — อนุมัติการปรับปรุงบัญชีที่ปิดแล้ว) กับ "Loan Officer" (อนุมัติใบสมัครตอนยื่นกู้ ตาม BR-miniloan-011@v1) เป็นคนละบทบาทกัน — แยกนิยาม เขียน not_to_confuse_with กันไว้ · เปิดคำศัพท์ใหม่ UL-miniloan-026 (Loan Officer) เพราะไม่เคยมี UL id แยกมาก่อนทั้งที่ถูกอ้างถึงเป็น actor ตลอดทั้งสเปก สรุป: แปลงชุด actor ที่ยืนยันแล้วในข้อ [1] เป็น stakeholders[] (STK-miniloan-001..005) ตามที่ capture-flow.md ระบุว่าชั้น 1 framing เป็นผู้เติมฟิลด์นี้ — ไม่รวม Web/API เพราะเป็นชั้นสถาปัตยกรรม ไม่ใช่ party ที่มีสิทธิ์แยกจากกัน (REQ-miniloan-006: Web ไม่ถือกฎเอง เรียกผ่าน API เท่านั้น)
