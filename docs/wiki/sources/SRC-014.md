## เนื้อความ

> บันทึกรอบ /req:ask ชั้น 1 หมวด language (2026-08-15) — เจ้าของสเปกตอบในแชท ยิง QB-lang-01 สามครั้ง หนึ่งครั้งต่อหนึ่งคู่คำที่ชนกัน ตามที่คลังคำถามอนุญาตไว้ ("This is the one tier 1 question worth firing more than once in a session — once per colliding pair the input contains") ชั้น 1 ยังเป็น status: provisional · field_evidence: null — คำถามมาจากการ์ดสอน ไม่ใช่จากงานลูกค้าจริง คำตอบดิบที่เจ้าของพิมพ์: "1. a,2 b,3 a" [1] QB-lang-01 · คู่ที่ 1 — "ยอดคงเหลือ" กับ "เงินต้นคงเหลือ" เป็นสิ่งเดียวกันไหม     ทั้งสองคำอยู่ในเอกสารต้นทางจริง และไม่มีคำไหนอยู่ใน glossary เลย     SRC-001 บรรทัด 113 §5 BR-06 : "แต่ละงวดแยกเป็นดอกเบี้ย (ยอดคงเหลือ × r) และเงินต้น (EMI − ดอกเบี้ย)"     SRC-001 บรรทัด 117 §5 BR-07 : "ยอดปิดบัญชี = เงินต้นคงเหลือ + ดอกเบี้ยค้างจ่ายถึงวันที่ปิด + ค่าธรรมเนียมปิดก่อนกำหนด (สมมติ 1% ของเงินต้นคงเหลือ)"     SRC-001 บรรทัด 76 · 197 : ตารางผ่อนมีคอลัมน์ ต้น/ดอก/ยอดคงเหลือ · "ยอดคงเหลือหลังงวดสุดท้าย = 0"       ⭐ a) สิ่งเดียวกัน — ใช้คำเดียวทั้งเอกสาร โค้ด และ UI   [ดาวมาจาก SRC-001 บรรทัด 113: ดอกเบี้ยคิดจาก ยอดคงเหลือ × r ซึ่งเป็นสูตรลดต้นลดดอก จะถูกก็ต่อเมื่อ ยอดคงเหลือ หมายถึงเงินต้นที่เหลือ]          b) คนละสิ่ง — แยกนิยาม และเขียน "ห้ามสับสนกับ" กันไว้ (ถ้าเป็นแบบนี้ สูตรใน BR-miniloan-016@v1 ผิด)          c) ซ้อนกันบางส่วน — คำหนึ่งเป็นส่วนหนึ่งของอีกคำ          z) ยังไม่แน่ใจ / ต้องถามลูกค้า       → ตอบ a : สิ่งเดียวกัน ใช้คำเดียวทั้งระบบ [2] QB-lang-01 · คู่ที่ 2 — "เงินต้น (P)" กับ "จำนวนเงินกู้ที่ขอ (RequestedAmount)" เป็นสิ่งเดียวกันไหม     ไม่มีดาว — อินพุตเงียบ เอกสารต้นทาง §5 BR-06 เขียนแค่ "P = เงินต้น" ไม่เคยบอกว่า P มาจากยอดไหน     บริบท: BR-miniloan-012@v1 ให้เจ้าหน้าที่ปรับวงเงินลงก่อนอนุมัติได้ · คำตอบ Q-miniloan-002 ยอมรับว่า "DTI ที่บันทึกไว้ผูกกับยอดที่ขอ ไม่ใช่ยอดที่อนุมัติจริง" — ระบบมีตัวเลขสามตัว (ที่ขอ · วงเงินสูงสุด UL-miniloan-010 · ที่อนุมัติจริง) แต่คำศัพท์มีสองตัว          a) สิ่งเดียวกัน — ปรับวงเงินคือแก้ตัวเลขในใบสมัครทับลงไป ยอดที่ขอหลังปรับ = P          b) คนละสิ่ง — แยกนิยาม เพิ่มคำใหม่สำหรับยอดที่อนุมัติจริง และเขียน "ห้ามสับสนกับ" กับ UL-miniloan-011 ไว้          c) ซ้อนกันบางส่วน — ปกติเท่ากัน ต่างกันเฉพาะใบที่ถูกปรับวงเงิน          z) ยังไม่แน่ใจ / ต้องถามลูกค้า       → ตอบ b : คนละสิ่ง ต้องมีคำใหม่สำหรับยอดที่อนุมัติจริง [3] QB-lang-01 · คู่ที่ 3 — "ผู้สมัคร (Applicant)" กับ "ผู้กู้" เป็นสิ่งเดียวกันไหม     ไม่มีดาว — อินพุตเงียบ เอกสารต้นทางใช้ ผู้สมัคร 7 ครั้ง · ผู้กู้ 0 ครั้ง · ลูกค้า 0 ครั้ง     ส่วน spec.json ใช้ ผู้สมัคร 39 ครั้ง · ผู้กู้ 21 ครั้ง · ลูกค้า 6 ครั้ง — คำว่า "ผู้กู้" เราเขียนขึ้นเองระหว่างเก็บกฎ ไม่ได้มาจากลูกค้า          a) สิ่งเดียวกัน — เลือกคำเดียวใช้ทั้งระบบ แล้วอีกคำเป็นแค่ aka (ถ้าเลือกข้อนี้ บอกด้วยว่าจะใช้คำไหนเป็นคำหลัก)          b) คนละสิ่ง — Applicant คือคนก่อนเบิกจ่าย · ผู้กู้ คือคนหลังมีบัญชีแล้ว          c) ซ้อนกันบางส่วน — คนเดียวกันแต่คนละบทบาทตามช่วงเวลา          z) ยังไม่แน่ใจ / ต้องถามลูกค้า       → ตอบ a : สิ่งเดียวกัน · เจ้าของไม่ได้ระบุว่าคำไหนเป็นคำหลัก ผู้ถามเลือก "ผู้สมัคร / Applicant" จากอินพุต (SRC-001 บรรทัด 57 §3 ตาราง actor: "**Applicant** \| ผู้สมัครสินเชื่อ กรอกและยื่นใบสมัคร ดูสถานะ" — เป็นคำเดียวที่เอกสารต้นทางใช้) และบันทึกไว้ว่าเป็นการอ่าน ไม่ใช่คำตอบ รอเจ้าของยืนยันคำเดียว
